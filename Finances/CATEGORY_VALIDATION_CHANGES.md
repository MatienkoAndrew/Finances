# Изменения: Валидация существования категорий

## Проблема
При импорте Kaspi-документов `ExpenseCategoryGuesser` подставлял категории (например, "Кофе"), которые пользователь уже удалил из базы данных. Это приводило к созданию транзакций с несуществующими категориями.

## Решение
Добавлена проверка существования категории перед её применением к транзакции.

## Измененные файлы

### 1. CategoryRuleEngine.swift
- Добавлен параметр `existingCategories: [ExpenseCategoryItem]`
- Добавлена проверка: угаданная категория применяется только если она существует в базе
- Если категория не найдена в базе, возвращается `nil`

### 2. PDFImporter.swift
- В `importTransactions()` добавлен параметр `categories: [ExpenseCategoryItem]`
- В `makeTransaction()` добавлен параметр `categories: [ExpenseCategoryItem]`
- Все вызовы `CategoryRuleEngine.matchCategoryName()` теперь передают список категорий

### 3. TransactionsView.swift
- Добавлен `@Query` для загрузки категорий из SwiftData
- Список категорий передается в `PDFImporter.importTransactions()`

## Результат
Теперь при импорте:
1. Сначала проверяются пользовательские правила (CategoryRule)
2. Затем `ExpenseCategoryGuesser` пытается угадать категорию
3. **Новое:** Угаданная категория применяется только если она существует в базе
4. Если категория не найдена, транзакция создается без категории (можно назначить вручную)

## Дополнительные улучшения
В `ExpenseCategoryGuesser.swift` все еще есть хардкоженные правила. Если нужно изменить логику угадывания (например, направить "COFFEE" в "Еда" вместо "Кофе"), можно:
- Создать CategoryRule с высоким приоритетом
- Или изменить код в ExpenseCategoryGuesser напрямую
